# merkle-tree-v1

**Статус:** frozen (Gate B)
**Реализации:** `crates/merkle` (Rust), `packages/merkle-ts` (TypeScript, Gate B)
**Векторы:** `spec/vectors/merkle.json`

## 1. Хэши

```text
leaf_hash(commitment) = SHA-256(0x00 || commitment)      // RFC 6962
node_hash(left, right) = SHA-256(0x01 || left || right)  // RFC 6962
```

Доменное разделение `0x00` / `0x01` обязательно: без него внутренний узел
предъявляется как лист, и доказательство включения теряет смысл.

## 2. Форма дерева

Дерево строится уровнями снизу вверх. На каждом уровне соседние узлы
попарно хэшируются. **Непарный последний узел поднимается на следующий
уровень без хэширования.**

Дублирование последнего узла (Bitcoin-style) **запрещено**: оно делает
деревья из `n` и `n+1` листьев с повторённым последним листом
неразличимыми по корню.

Дерево без листьев не определено. Пустой batch не создаётся (§2.5 плана),
запись без полей отклоняется.

Пример на 5 листьях:

```text
level0: l0 l1 l2 l3 l4
level1: H(l0,l1)  H(l2,l3)  l4            ← l4 поднят
level2: H(H01,H23)          l4            ← l4 поднят снова
root  : H( H(H01,H23), l4 )
```

## 3. Порядок листьев

Порядок задаётся вызывающим и нормативен для каждого дерева отдельно:

| Дерево | Порядок листьев |
|---|---|
| field tree | по `path_bytes` (байтово, после NFC + UTF-8) |
| batch tree | по `(record_id_commitment, record_version)` |

## 4. Доказательство включения

Proof — последовательность шагов снизу вверх; каждый шаг несёт хэш соседа
и сторону (`LEFT` / `RIGHT`), с которой сосед стоит. Для уровня, где узел
поднимается без пары, шага в proof **нет**.

Проверка: пересчитать корень из листа и шагов, сравнить с ожидаемым.
Никакого другого условия проверка не содержит — в частности, длина proof
не является признаком корректности.
