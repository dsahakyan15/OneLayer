# canonical-record-v1

**Статус:** draft (замораживается на выходе Gate B)
**Реализации:** `crates/canonical` (Rust), `packages/canonical-ts` (TypeScript, Gate B)
**Векторы:** `spec/vectors/canonical.json`

Документ задаёт единственную нормативную сериализацию канонической версии
записи. Обе реализации пишутся по этому тексту, а не друг по другу.

## 1. Профиль CBOR

Deterministic CBOR по **RFC 8949 §4.2.1** (core deterministic encoding).
RFC 7049 не применяется: правило сортировки ключей map там другое, и
реализация по нему даст иные байты на тех же данных.

Обязательные правила:

1. Заголовок (major type + argument) кодируется в **кратчайшей** форме.
2. Indefinite-length кодирование запрещено.
3. Ключи map сортируются **байтово по закодированному ключу**, не по строке.
   Следствие: `"z"` (`617a`) идёт раньше `"aa"` (`626161`), хотя по строкам
   порядок обратный.
4. Ключи map — только текстовые.
5. Floating point запрещён полностью. Числа с дробной частью передаются
   строкой (см. §3), поэтому недетерминированного binary64 не возникает.
6. Отсутствующий ключ и `null` различаются: `null` кодируется как `0xf6`,
   отсутствующий ключ в map не появляется. Их обязательства различны.

## 2. Строки

* Нормализация — **NFC**, применяется до кодирования и до измерения длины.
* Кодировка — UTF-8.
* NFKC не применяется: армянская лигатура U+0587 остаётся одним символом,
  и совместимая декомпозиция не должна менять commitment.
* Все длины в протоколе — `byte_len` **после** NFC и UTF-8. Ни число
  code points, ни `String.length` в JavaScript нормой не являются.

## 3. Типы значений

| Тип | Представление |
|---|---|
| Строка | text string, NFC |
| Целое | major type 0/1, кратчайшая форма |
| Decimal | **строка** с фиксированным scale: `"0.10"` ≠ `"0.1"`, `"-0"` ≠ `"0"` |
| Timestamp | строка RFC 3339, UTC, без дробной части: `2026-07-31T00:00:00Z` |
| Булево | `0xf4` / `0xf5` |
| Отсутствие значения | `0xf6` (`null`) — только если ключ присутствует |
| Массив | definite length, **порядок значим** |
| Структура | map, ключи по §1 п. 3 |

Decimal и timestamp — строки, потому что и то и другое имеет представления,
различимые семантически и неразличимые после нормализации в число.

## 4. Поля вне схемы

Поле, отсутствующее в схеме реестра, — ошибка `CANONICALIZATION_FAILED`, а не
игнорируемое значение. Молчаливое отбрасывание означало бы, что anchored
состояние не покрывает часть данных.

## 5. Сортировка массивов

`rights`, `encumbrances`, `subjectCommitments` сортируются по правилам,
задаваемым схемой реестра (закрывается вместе с `OL-A-02`). До закрытия
порядок считается значимым и сохраняется как есть.

## 6. Ошибки

| Код | Условие |
|---|---|
| `CANONICALIZATION_FAILED` | поле вне схемы, `byte_len(path) > 65535`, целое вне диапазона CBOR, недопустимый тип значения |
