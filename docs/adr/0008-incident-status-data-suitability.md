# ADR-0008. RESOLVED не восстанавливает пригодность данных

Дата: 2026-09-24. Статус: accepted (решение владельца).

Закрытие расследования означает, что работа по инциденту завершена; оно не меняет байты ранее опубликованных данных. Поэтому пригодность данных в suspect-диапазоне определяется так:

| Статус incident | Данные в suspect-диапазоне |
|---|---|
| OPEN | заблокированы до выяснения |
| CONFIRMED | заблокированы |
| RESOLVED | остаются заблокированными |
| FALSE_POSITIVE | этот incident больше не блокирует |

FALSE_POSITIVE не дает автоматического CURRENT: остаются проверки других incidents, актуальности, отзыва и доверия. Исправленные данные публикуются новой версией в новом batch вне suspect-диапазона; старый сертификат сохраняет историю проблемы. Правило одинаково применяется в verifier, выборе recovery anchor, выборе доверенного snapshot и в legacy API: ни один путь не превращает RESOLVED в «чисто».

Отвергнуто: RESOLVED снимает блокировку, как FALSE_POSITIVE, — административное закрытие незаметно легализовало бы поврежденную историю. Подписанный remediation manifest (`resolution_hash`) возможен позже как versioned расширение, но не входит в первый production-релиз.
