# ADR-0007. Устанавливаемое приложение с серверной проверкой разрешений

Дата: 2026-09-19. Статус: accepted для продуктовой границы; конкретный desktop stack — proposed до compatibility spike.

Пользователь определил OneLayer как устанавливаемую программу для сотрудников, администраторов, аудиторов и хранителей ключей. Внешние лица получают результат через сотрудника; private network/device boundary из ADR-0006 сохраняется. Все штатные действия доступны через ролевые представления программы, но каждое разрешение на действие, объект и поле проверяет backend.

Tauri 2 с повторным использованием React UI — кандидат, а не утвержденный выбор для защищенного клиента. Второй кандидат — native UI (например, Qt Widgets без WebEngine). Выбор требует одинаковых испытаний подмены действия при скомпрометированном renderer, доверенного подтверждения подписи и хранения токенов; предварительная проверка окружения не заменяет эти испытания. Он требует отдельной проверки корпоративного входа, поддерживаемых ОС, signer и подписанных обновлений; существующий Next.js server/proxy остается на сервере. Альтернатива «обернуть текущий сайт WebView и считать скрытые кнопки защитой» отвергнута, поскольку она не обеспечивает native lifecycle и серверное разделение полномочий.

Установка приложения не выдает разрешений, не заменяет managed-device admission и не дает доступ к keys. Key Holder передает только собственную долю в изолированную Recovery Operation; ни desktop renderer, ни обычный API не становятся общим хранилищем пяти shares. Обоснование и этапы — [полный пайплайн](../application-pipeline-ru.md).

Предварительные ограничения Linux-окружения и критерии сравнения: [desktop preflight](../../.scratch/production-desktop/evidence/02/preflight.md). Установщик, SSO, signer и подписанное обновление пока не проверены.

2026-09-24: по решению пользователя первая production-версия предназначена для Linux. Первая целевая конфигурация — Linux Mint 22.1 x86_64, установленная на его текущем рабочем месте; на ней выполняются spike и приемка установленного приложения. Windows и macOS отложены за пределы первого выпуска, другие Linux-дистрибутивы требуют отдельной проверки. Это позволяет проверять приложение на реально доступной ОС. Выбор ОС принят; выбор Tauri/Qt остается proposed до compatibility spike. Поддержка целевой конфигурации считается подтвержденной после проверки установки, SSO, credential store, signer и подписанных обновлений; способ управляемой установки и device enrollment еще предстоит определить.

2026-09-24 (дополнение): Tauri 2 + React — основной кандидат для desktop; окончательный выбор после сравнительных испытаний ticket 02. Qt Widgets выбирается, если организация запрещает WebView или испытания покажут существенное преимущество Qt на целевом рабочем месте. Независимо от toolkit: токены и ключи недоступны обычному UI; сервер проверяет права на каждое действие; signer получает неизменяемый intent; существенные параметры подтверждаются вне потенциально захваченного UI; подписываются именно подтвержденные bytes. Диалог в том же скомпрометированном процессе не становится доверенным только потому, что он native. Первая production-ОС остается Linux Mint 22.1 x86_64 (решение выше); одновременная поддержка нескольких ОС не обещается.
